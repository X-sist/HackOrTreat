# T05 handoff: receiver implementation

## Result

Implemented `rx/rx.ino` using IRremote 4.7.1 and the generated shared protocol
header. The Rx uses D3, accepts full NEC/NEC2 frames with the `0xA700` address
prefix (IRremote classifies closely-spaced full frames as NEC2), assembles
sequential indexed bytes, checks protocol type/length/CRC
and printable nonblank text, and emits the shared Rx events. It reports restart,
index-gap, inter-symbol-timeout, packet-timeout, checksum, invalid-text,
unsupported-type, and identity-conflict outcomes. Unknown IR traffic and total
loss remain silent. `HELLO` returns the Rx hello event; unsupported serial
commands produce the shared error event.

Duplicate tracking uses 32 bounded identity/fingerprint entries and the shared
60-second TTL. No protocol fields, generated files, or contract pins changed.

## Verification

- `python firmware/verify.py --ci`: PASS, compiling both Tx and Rx on Uno R3
  with Arduino CLI 1.5.1, AVR core 1.8.8 and IRremote 4.7.1.
- Tx compile: 5,014 bytes flash, 784 bytes static RAM.
- Rx compile: 10,896 bytes flash, 1,230 bytes static RAM, leaving 818 bytes
  for stack/runtime.
- Shared repository and protocol-vector checks: PASS.
- User clarified the board roles after earlier tests: Rx is COM4 and Tx is
  COM5. Earlier no-frame tests used the reversed role assignment and are not
  valid evidence about the intended pair. Correct firmware was uploaded to
  both boards and each reported the expected role in its `hello` event.
- A production short-packet transfer emitted the exact Rx `message` event.
  Re-sending the same session/sequence/payload emitted `duplicate`; reusing the
  same identity with different payload emitted `protocol_error` / `ID_CONFLICT`.
- The first corrected transfer attempt exposed that IRremote classified
  closely-spaced full frames after index 0 as NEC2 (`protocol=8`, flag `0x21`).
  Rx had filtered them as repeats. The implementation now accepts full NEC2
  frames while excluding short NEC repeats.
- Raw decoder diagnostics showed all 59 indexed symbols in order for a
  maximum-length 48-byte packet.
- An initial production maximum-payload run had 2/3 successful attempts and
  one inter-symbol timeout. Afterward, eight consecutive 48-byte maximum
  payloads in one serial session all produced exact `message` events. This is
  successful bench evidence, though not a statistically robust reliability
  claim. The user reported the modules were currently less than 0.5 m apart;
  exact distance during the run was not measured.
- During 15 seconds of idle observation, neither board emitted unexpected
  events.
- A clear-path production short-message control passed immediately before the
  physical obstruction trial. While the user blocked the path for about three
  seconds during a maximum-size transmission, Tx emitted `accepted`/`sent` and
  Rx emitted no message for that packet. Once the path was clear, the next
  short production packet arrived with the exact payload. This confirms
  blocked-path loss and recovery at the close bench setup (sequences 69 and 70);
  the interval was approximate and no range or reliability claim follows from
  one trial.
- A temporary Tx diagnostic sent a five-symbol partial packet, a full packet
  with a corrupted CRC, a packet with an omitted index, and a deliberately
  slow partial packet. Rx reported respectively `INTER_SYMBOL_TIMEOUT`,
  `CRC_MISMATCH`, `INDEX_GAP`, and `PACKET_TIMEOUT` (the last after about
  9.1 seconds).
- After all diagnostic malformed packets and their timeouts, the production
  Tx/Rx pair delivered another valid message successfully.
- The production Rx sketch is restored on COM4. Tx remains on COM5. The
  temporary diagnostic sketch was removed.
- Longer optical range, ambient-light behavior, and measured worst-case timing
  have not been tested.

## Status

T05 is complete for its defined real-world transfer/disturbance acceptance.
Real two-board tests verified message delivery, duplicate detection,
ID-conflict reporting, eight consecutive maximum-size messages at the
user-reported close bench setup (<0.5 m),
15-second idle silence, controlled partial/corrupt/gap/whole-packet-timeout
events, a user-operated physical obstruction during a maximum-size send, and
successful recovery to a subsequent valid message. Longer range,
ambient-light behavior, measured worst-case timing, and manufacturer
pinout/electrical documentation remain unverified and are not represented as
tested.
